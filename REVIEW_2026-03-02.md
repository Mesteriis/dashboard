### 2. Архитектурные замечания (P1-P2)

#### a) Монолитный backend с элементами микросервисов

**Проблема**: Смешаны API layer, business logic, и integration layer

```
backend/
├── api/v1/           # API Layer
├── apps/health/      # Business Logic
├── core/bus/         # Integration Layer
├── core/plugins/     # Business Logic + Integration
└── db/               # Persistence Layer
```

**Влияние**: Сложность масштабирования, тестирования отдельных компонентов  
**Рекомендация**: Рассмотреть выделение worker в отдельный сервис при масштабировании

#### b) Plugin system без sandboxing

**Проблема**: Плагины выполняются в том же процессе что и backend

```python
# backend/plugins/loader.py
def load_plugin(plugin_dir: Path) -> PluginInstance:
    spec = importlib.util.spec_from_file_location(
        plugin_name, 
        plugin_dir / "__init__.py"  # ← прямой импорт в процесс
    )
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)  # ← выполнение в основном процессе
```

**Влияние**: Уязвимый плагин может компрометировать весь backend  
**Рекомендация**:
- Краткосрочно: Строгая валидация манифестов
- Долгосрочно: Plugin isolation через subprocess или WebAssembly

#### c) Health monitoring без адаптивности

**Проблема**: Фиксированные интервалы проверок

```python
# .env.example
OKO_HEALTH_SCHEDULER_TICK_SEC=5        # ← фиксированный тик
OKO_HEALTH_SCHEDULER_HEARTBEAT_SEC=30  # ← фиксированный heartbeat
```

**Влияние**: Избыточная нагрузка при большом количестве сервисов  
**Рекомендация**: Реализовать adaptive scheduling на основе количества сервисов

### 4. Безопасность (P1-P2)

#### a) Capability headers в plain text

```bash
curl http://127.0.0.1:8000/api/v1/state \
  -H 'X-Oko-Actor: local-dev'      # ← передается открыто
  -H 'X-Oko-Capabilities: read.state'  # ← без шифрования
```

**Влияние**: MITM атаки в production  
**Рекомендация**:
- Требовать HTTPS для production
- Рассмотреть token-based authentication (JWT)

#### b) Plugin store без верификации подписей

**Проблема**: Плагины загружаются без криптографической проверки

```python
# backend/core/plugins/store.py
async def install_plugin(plugin_id: str) -> PluginInstallationResult:
    # ← нет проверки подписи
    plugin_data = await store_client.download_plugin(plugin_id)
    installer.install(plugin_data)
```

**Влияние**: Риск установки модифицированных плагинов  
**Рекомендация**: Реализовать code signing для плагинов из Store

#### c) GITHUB_TOKEN в .env.example

```bash
# .env.example
GITHUB_TOKEN=  # ← должен быть в .gitignore
```

**Влияние**: Разработчики могут закоммитить токен  
**Рекомендация**: Удалить из example, добавить проверку в pre-commit

### 5. Производительность (P2-P3)

#### a) Broker prefetch count

```bash
OKO_BROKER_PREFETCH_COUNT=32  # ← может быть недостаточно
```

**Влияние**: Ограниченная пропускная способность при high-load  
**Рекомендация**: Тестирование под нагрузкой, настройка динамически

#### b) RPC timeouts

```bash
OKO_STORAGE_RPC_TIMEOUT_SEC=2.0   # ← мало для медленных операций
OKO_ACTION_RPC_TIMEOUT_SEC=5.0    # ← может прерывать долгие действия
```

**Влияние**: False failures при временных задержках  
**Рекомендация**: Retry logic с exponential backoff

#### c) Health scheduler

```bash
OKO_HEALTH_SCHEDULER_TICK_SEC=5  # ← 5 секунд для всех сервисов
```

**Влияние**: N сервисов × 5 сек = нагрузка растет линейно  
**Рекомендация**: Staggered scheduling, адаптивные интервалы

## 💡 Рекомендации

### Для немедленного улучшения

1. **Автоматизировать исправление линтеров** в CI:
   ```yaml

   ```

2. **Добавить pre-commit hook** для проверки console.log:
   ```bash
   # .pre-commit-config.yaml
   - id: no-console-log
     name: Check for console.log
     entry: grep -r "console\.log" frontend/src/
     language: system
   ```

3. **Создать шаблон `_dashboard.yaml.example`**:
   ```yaml
   # _dashboard.yaml.example
   version: "1.0"
   services: []
   actions: []
   ```

1. **Рассмотреть модульную декомпозицию**:
   ```
   oko-backend/          # Core API
   oko-worker/           # Background jobs

   ```
